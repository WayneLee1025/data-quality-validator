# 评测集：金融监管制度问答

把「AI 答得好不好」拆成三层来量，是这个目录唯一的目的。

## 为什么做这个

大多数人的 AI 项目停在「我调了个接口，它能回答」。面试官追问一句「你怎么知道它答得对」，就答不上来了。

这里做的不是又一个问答 demo，是**评测**：定义什么叫答对、造出会答错的题、把失败原因分类。这是 AI 应用岗 JD 里反复出现的能力项。

**获取方式**：

```bash
python fetch_docs.py      # 自动抓取 A、B 并清洗到 docs/
```

- **A / B**：脚本从中国政府网公开页面抓取正文，自动去掉导航并去重（页面会输出 PC/移动两份）。存到 `docs/`，该目录在 `.gitignore` 里，**不进公开仓库**。
- **C**：标准全文是 PDF，需手动下载放入 `docs/`。公开转载链接：`https://www.bankofbbg.com/bbgow/attachDir/2025/12/2025121119260258743.pdf`（以全国金融标准化技术委员会原文为准）。

**合规声明**：只用上述公开文件。本地存文本是为了做检索，不随仓库分发。不含任何机构的内部制度、表名、规则内容、系统代号。这是硬约束——违反即整个项目作废。

## 30 题的结构

| 类型 | 数量 | 考什么 |
| --- | --- | --- |
| 有答案 | 18 | 文档里能查到，考基本检索与引用 |
| 无答案 | 6 | 文档里根本没有，考**敢不敢说不知道** |

「无答案」那 6 题是这个评测集最值钱的部分。模型最容易犯的错不是找不到，是找不到还硬编。

## 怎么跑

```bash
# 流程验证（不调模型，几秒出报告）
python run_eval.py

# 真实评测（需要 API key）
set OPENAI_API_KEY=你的key
python run_eval.py --api
```

输出 `report.md`，包含总览、分类型统计、逐题明细、失败案例。

## 三层指标，别混成一个「对/错」

| 指标 | 含义 | 为什么单独记 |
| --- | --- | --- |
| 检索命中 | 有没有从文档里找到相关段落 | 找不到 → 该补切块和召回 |
| 有效作答 | 有没有给出回答 | 无答案题拒答才算对 |
| 答案正确 | 要点是否覆盖 | 检索到了但用错，是另一类问题 |

三项混成一个准确率，就永远不知道该修哪一层。

## 诚实边界

- `report.md` 里的 MOCK 数字**不是模型能力**，只证明流程能跑通。
- 真实数字要在接入 API、准备好语料后重跑，**照实写，不挑好看的题**。
- CSV 里标 `⚠️` 的条目（时限、频次、文号）必须回原文核对后才能写进简历或面试话术。模型和我都可能记错。
