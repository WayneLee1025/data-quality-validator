# 评测集：金融监管制度问答

把「AI 答得好不好」拆成三层来量，是这个目录唯一的目的。

## 为什么做这个

大多数人的 AI 项目停在「我调了个接口，它能回答」。面试官追问一句「你怎么知道它答得对」，就答不上来了。

这里做的不是又一个问答 demo，是**评测**：定义什么叫答对、造出会答错的题、把失败原因分类。这是 AI 应用岗 JD 里反复出现的能力项。

```bash
pip install pypdf
```

- **C**：标准全文是 PDF，脚本按「先判文字层 → 去页眉页脚 → 不做段落合并」三步处理。公开转载链接：`https://www.bankofbbg.com/bbgow/attachDir/2025/12/2025121119260258743.pdf`（以全国金融标准化技术委员会原文为准）。

三份文本都存到 `docs/`，**该目录在 `.gitignore` 里，不进公开仓库**——公开的是处理代码，不是条文转存。

## 切块与检索基线

```bash
python chunk.py                 # → chunks.jsonl（185 块）
python retrieval.py             # 抽检 9 道已核题的检索命中率
python retrieval.py --ask "C3类信息能否委托处理"   # 单条查询看召回
```

**切块按结构，不按字数**。监管文件的一条就是一个完整要求，按固定长度切会把「C3 不得委托」和「委托需去标识化」切进两个块，检索到任一块都答不全。

| 文件 | 块数 | 对齐情况 |
| --- | --- | --- |
| A | 81 | 与原文 81 条一一对应 |
| B | 55 | 与原文 55 条一一对应 |
| C | 49 | 按 4.x / 6.x / 7.x 节切 |
| 合计 | 185 | 平均 209 字 |

**第一层指标已经有真实数字了**（BM25 + 中文字符二元组，不调模型）：

| 指标 | 结果 |
| --- | --- |
| recall@3 | 6/9 = 66.7% |
| recall@5 | 7/9 = 77.8% |

**3 道未命中的题全部落在「跨文档」和「版本冲突」两类**。原因很清楚：这两类题的题面用的是业务说法（「监管口径是否一致」），条文里根本没有这些词，词法检索匹配不上。切块本身没问题——已核的 9 道题答案 100% 落在某个完整块内。

这就是下一步该上向量检索和查询改写的依据，不是拍脑袋换方案。

## 三层指标，别混成一个「对/错」

| 指标 | 含义 | 为什么单独记 |
| --- | --- | --- |
| 检索命中 | 有没有从文档里找到相关段落 | 找不到 → 该补切块和召回 |
| 有效作答 | 有没有给出回答 | 无答案题拒答才算对 |
| 答案正确 | 要点是否覆盖 | 检索到了但用错，是另一类问题 |

三项混成一个准确率，就永远不知道该修哪一层。

## 诚实边界

- `report.md` 里的 MOCK 数字**不是模型能力**，只证明流程能跑通。
- 真实数字要在接入 API、准备好语料后重跑，**照实写，不挑好看的题**。
- 答案要点里的时限、频次、文号必须回原文核对后才能写进简历或面试话术。模型和我都可能记错——本轮核对时就把 A 的施行日期记错过一次（实际是 2024-12-27 公布即施行），已按原文改正。

## 题目与原文的对应关系

30 题里有 9 题直接依赖 A/C 两文，已逐条回原文核过（2026-11-16）：

| 题号 | 考点 | 出处 |
| --- | --- | --- |
| Q13–Q15 | 分类、C3 内容、生命周期 | C 4.2 / 4.3 |
| Q16 | 传输技术要求 | C 6.1.2 |
| Q17 | 委托处理六项要求 | C 6.1.4.4 |
| Q26 | 标准与办法的层级衔接 | C 4.2、6.x + A 第十八条 |
| Q27 | 泄露事件双重要求 | A 第六十九条 + C 6.x / 7.4 |
| Q28 | 外包三项叠加 | A 第 22 / 30 / 31 条 + B 第三、四章 + C 6.1.4.4 |
| Q30 | 两套分类口径 | C 封面日期 + 4.2 节、A 第十八条 |

**Q27 是最值得拿来讲的一题**：办法给了 2 小时 / 24 小时 / 每 2 小时 / 5 个工作日的硬时限，技术规范只写「及时」、没有任何小时数。模型最常见的错是把办法的时限搬到标准头上——这种「张冠李戴」比说不知道更危险。
