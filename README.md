# python-journey · 数据质量校验器

> 李邦都的 Python 学习仓库（B 方案）。每个知识点以「可运行脚本 + 真实数据」沉淀，不做空笔记。
> 本仓库的第一个实战工具：**监管报送数据质量校验器**——把银行报送前置质检的 6 类规则，用 pandas 复刻成可复用脚本。

## 这个工具解决什么

监管报送前，客户/账户/交易三类抽取数据常混入空值、重复主键、证件号位数错、日期格式乱、取值域越界、外键断裂、金额负值等脏数据。手工排查慢且漏。
本脚本用向量化校验一次性抓全，跑一遍即可输出违规明细清单，并用非零退出码把结果交给外部调度 / CI。

## 数据质量保障体系

把这套校验向上通用化，可归到数据质量保障体系的四层：

| 能力层 | 本仓库的实现 | 输出 |
|---|---|---|
| **完整性校验** | 13 个关键字段非空（客户 4 / 账户 4 / 交易 5）+ 主键唯一性（cust_id / acct_no / txn_id） | 逐字段违规明细行 |
| **一致性校验** | 引用完整性：`acct.cust_id → cust`、`txn.acct_no → acct`；代码型字段统一按字符串读取，避免 `"01"` 被推断成 `1` 造成跨表类型漂移 | 断裂外键明细行 |
| **异常检测** | 规则型 / 点异常：证件号长度 ≠ 18、日期不匹配 `YYYY-MM-DD`、status / txn_type 越界、金额与余额为负 | 异常记录明细 + 命中条数 |
| **自动化质量巡检** | 单命令批量执行：`--data` 指向任意一批抽取样本，6 类规则一次跑完；**有违规退出码 `1`，全通过退出码 `0`**，可直接接 cron / Airflow / DolphinScheduler 做报送前每日巡检与失败告警 | 控制台违规清单 + 退出码 |

**一稿两用的口径**：这四层对应的是「数据质量保障体系 / 异常检测 / 完整性校验 / 一致性校验 / 自动化巡检」这类通用岗位要求；落到金融场景就是监管报送前置质检（78 条 PL/SQL 规则的 pandas 版雏形）。

**当前边界（不夸大）**：

- 规则为**硬编码**的 6 类，尚未抽成码表驱动，新增规则要改 `main()`；
- 异常检测是**规则型**（点异常），不含跨批次波动、均值漂移等统计型检测；
- 无内置调度器，巡检由外部调度触发；无落库、无报表持久化；
- 单机单批次三表，不含增量比对与跨源对账。

## 功能

`week3_validation.py` 实现 6 类报送质检规则：

| 规则 | 说明 |
|------|------|
| 非空校验 | 关键字段（客户号/账户号/金额等）不允许空 |
| 唯一性 | 主键（cust_id / acct_no / txn_id）不重复 |
| 格式校验 | 证件号 18 位、日期 `YYYY-MM-DD` |
| 取值域 | status / txn_type 等枚举值合法 |
| 外键 | 账户→客户、交易→账户 引用完整 |
| 业务规则 | 交易金额 ≥ 0、余额符号合理 |

关键细节：代码型字段（id_no/status/txn_type）按**字符串读取**，避免 `"01"` 被 pandas 误转成 `1` 导致取值域全误报。

## 快速开始

```bash
# 默认读 data/ 示例（含 15 条植入违规）
PY week3_validation.py

# 指向你自己的报送抽取样本（任意三张表目录）
PY week3_validation.py --data 你的目录

# 退出码：0 = 全部通过；1 = 存在违规（接调度告警用）
echo $?
```

## 诚实边界（面试可如实说）

- 日期只查 `YYYY-MM-DD` 格式，不查语义合法性（`2024-13-01` 会漏），真上线需 `pd.to_datetime(errors="coerce")` 二审；
- 规则硬编码在 `main()`，下一步抽成码表驱动，可做成 78 条 PL/SQL 报送规则的 pandas 版雏形；
- 退出码只区分「有 / 无违规」，不区分严重等级，尚无分级告警。
